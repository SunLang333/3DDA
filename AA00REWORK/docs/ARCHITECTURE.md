# Architecture mapping

This document maps the three source-of-truth reference documents in `AA00REWORK/` to the implemented MVP.

## Core rule

> Model the world as a persistent semantic macro lattice, then lazily realize concrete local chunks from that semantic state, persisting only mutated local state.

That rule is implemented by the interaction between:

- `src/WorldGen.Core/Domain/WorldTypes.cs`
- `src/WorldGen.Core/Domain/MacroWorld.cs`
- `src/WorldGen.Core/Domain/LocalWorld.cs`
- `src/WorldGen.Core/Generation/Macro/MacroGenerationPipeline.cs`
- `src/WorldGen.Core/Generation/Local/LocalRealizer.cs`
- `src/WorldGen.Core/Services/ChunkManager.cs`
- `src/WorldGen.Persistence/FileChunkStore.cs`

## Macro / micro split

### Persistent macro layer

Implemented by:

- `WorldProfile`
- `MacroChunk`
- `SemanticParcel`
- `SemanticLayer`
- `ChunkFeatureSummary`
- `ChunkConnectivitySummary`

The macro layer stores semantic truth:

- landcover
- infrastructure
- parcel identity
- predecessor/layer history
- special ownership
- coarse connectivity
- full `ZBounds(-10, +10)` vertical semantic derivation

`MacroChunk` now stores only explicitly-authored or derived semantic parcels in a sparse `Dictionary<WorldCellCoordinate, SemanticParcel>`. Any unmaterialized coordinate resolves implicitly to the correct default surface / air / subterranean parcel for its z-level.

Macro chunks are generated by `MacroGenerationPipeline`, persisted immediately by `ChunkManager` through `FileChunkStore`, and treated as authoritative afterward.

### Lazy micro layer

Implemented by:

- `LocalChunk`
- `LocalCell`
- `LocalChunkProvenance`
- `LocalRealizer`

The local layer realizes one semantic parcel footprint at a time, keyed by a macro-scoped `LocalChunkKey(Macro, X, Y, Z)`. The realization path replays semantic layers in order and adds concrete structure, props, items, and fields.

Local chunks remain engine-neutral. They are intended to be consumed by a later engine adapter.

## The implemented 9-stage macro pipeline

`MacroGenerationPipeline` uses discrete stage classes implementing `IMacroGenerationStage`.

| Stage | Class | Current MVP behavior |
| --- | --- | --- |
| 1 | `InitializeLayersStage` | Leaves implicit default parcels unresolved so sparse storage stays compact |
| 2 | `CalculateDensityMetricsStage` | Computes deterministic `urbanity`, `forestosity`, and `hydrology` fields |
| 3 | `PlaceHydrologyStage` | Lays rivers/lakes with `LinearFeatureGraph` and marks watery parcels |
| 4 | `PlaceNaturalFeaturesStage` | Adds forest, wetland, and ravine semantics |
| 5 | `SeedSettlementsStage` | Seeds one settlement core and surrounding parcels when the density threshold is met, promoting dense cores into skyscraper anchors |
| 6 | `BuildInfrastructureStage` | Builds roads/highways, including bridge transitions over water and deterministic manhole anchors |
| 7 | `PlaceSpecialsStage` | Places a non-trivial `ResearchOutpost` special near road/forest transitions |
| 8 | `VerticalDerivationStage` | Applies declarative vertical extension rules across `z=-10..10` and generates independent sewer / subway networks with forked RNG streams |
| 9 | `FinalizeOvermapStage` | Final no-op placeholder in v1; the pipeline finalizes connectivity/provenance after stage execution |

## Determinism strategy

Implemented in `src/WorldGen.Core/Randomization/Randomization.cs`.

- `PhaseSeedDeriver` uses a stable 64-bit FNV-1a hash over `worldSeed`, chunk key, and phase name.
- `DeterministicRandomSource` uses a PCG-style 32-bit generator seeded from the derived 64-bit phase seed.
- Generation phases request independent RNG streams by phase name, and deeper subsystems such as sewer/subway routing fork dedicated substreams to avoid cross-phase coupling.
- Canonical equality is checked via `CanonicalWorldSerializer`, which serializes macro/local chunks into deterministic JSON byte sequences used by tests and reporting.

## Feature graphs

Implemented by `src/WorldGen.Core/Features/LinearFeatureGraph.cs`.

The MVP includes one reusable graph representation for:

- rivers
- roads
- highways
- sewer routing
- subway routing

The graph stores nodes and line segments, rasterizes them deterministically, and feeds the macro generator’s occupancy logic.

## Runtime orchestration

Implemented by `src/WorldGen.Core/Services/ChunkManager.cs`.

Responsibilities:

- register/load the active `WorldProfile`
- lazy-load chunks from persistence
- generate missing macro/local chunks asynchronously
- enforce single-flight generation per key under concurrency
- maintain LRU caches for macro and local chunks
- persist dirty local chunks and flush on disposal

## Persistence boundary

Implemented by `src/WorldGen.Persistence/FileChunkStore.cs`.

- `WorldProfile`, `MacroChunk`, and mutated `LocalChunk` payloads are written as binary MessagePack envelopes.
- Human-readable JSON sidecars summarize each stored payload.
- Local chunk elision is policy-driven and z-specific: if a local chunk at a particular `(macro, x, y, z)` is not dirty, `ChunkManager` deletes or omits only that persisted slice so it can be regenerated later.

## Godot boundary

The core contains no `Godot.*` references.

`src/WorldGen.Adapter.Godot/AdapterStub.cs` demonstrates the adapter direction by projecting `LocalChunk` into a `GodotChunkSceneBlueprint`. This is a placeholder for future `MeshInstance3D` / `Node3D` conversion work once a concrete Godot runtime/toolchain target is selected.
